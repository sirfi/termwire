# Termwire Protocol Documentation

## General Principles
- Message wrapper `Message` uses `body` oneof; each response includes `code` and optionally `message` ([protocol/termwire.proto#L10-L46](protocol/termwire.proto#L10-L46)).
- All amounts are in cents; currency is ISO 4217 alpha code (`currency`).
- Transaction ID is generated by ECR and remains constant throughout all steps.

## Response Codes
- `code`: ISO8583-style string; "00" success, "05" declined, "51" insufficient funds, "E01" timeout, etc.
- `message`: Human-readable description (can provide information even on success).

## Card Payment Flow
1) ECR → POS: `CardInsertionRequest` (amount, currency, transaction_id) ([protocol/termwire.proto#L56-L63](protocol/termwire.proto#L56-L63)).
2) POS → ECR: `CardInsertionResponse` (masked card, holder name, bank applications, code/message) ([protocol/termwire.proto#L65-L71](protocol/termwire.proto#L65-L71)).
3) ECR → POS: `PaymentProcessingRequest` (selected bank, loyalty points decision, AID, installment count) ([protocol/termwire.proto#L73-L79](protocol/termwire.proto#L73-L79)).
4) POS → ECR: `LoyaltyCardInquiryResponse` (available points, points value, code/message) ([protocol/termwire.proto#L81-L86](protocol/termwire.proto#L81-L86)).
5) ECR → POS: `LoyaltyPointsConfirmation` (points to use) ([protocol/termwire.proto#L88-L92](protocol/termwire.proto#L88-L92)).
6) ECR → POS: `PaymentCompletionRequest` (card/points amounts, total, currency, installments, transaction_id) ([protocol/termwire.proto#L94-L101](protocol/termwire.proto#L94-L101)).
7) POS → ECR: `PaymentCompletionResponse` (RRN/auth, receipt number, remaining points, currency, installments, code/message) ([protocol/termwire.proto#L103-L111](protocol/termwire.proto#L103-L111)).

## Refund / Void
- `RefundTransactionRequest`: original_transaction_id, refund_amount_cents, reason, currency, original_confirmation_code ([protocol/termwire.proto#L113-L119](protocol/termwire.proto#L113-L119)).
- `RefundTransactionResponse`: transaction_id, confirmation_code, currency, code/message ([protocol/termwire.proto#L121-L126](protocol/termwire.proto#L121-L126)).
- `VoidTransactionRequest`: original_transaction_id, reason, currency, original_confirmation_code ([protocol/termwire.proto#L128-L132](protocol/termwire.proto#L128-L132)).
- `VoidTransactionResponse`: transaction_id, confirmation_code, currency, code/message ([protocol/termwire.proto#L134-L138](protocol/termwire.proto#L134-L138)).

## Reports
- X Report (interim): transaction count, currency-based sales/refunds/voids totals, and payment method-currency breakdown ([protocol/termwire.proto#L142-L150](protocol/termwire.proto#L142-L150)). Does not reset counters.
- Z Report (end-of-day): same breakdowns + z_report_number ([protocol/termwire.proto#L154-L161](protocol/termwire.proto#L154-L161)). Resets counters.
- Total structures: `CurrencyTotals` (amount_cents, count) and `PaymentMethodTotals` (method, currency, amount_cents, count) ([protocol/termwire.proto#L191-L199](protocol/termwire.proto#L191-L199)).

## Detailed Report
- Request: time range, limit, cursor, include_voids, optional currency filter ([protocol/termwire.proto#L163-L169](protocol/termwire.proto#L163-L169)).
- Response entry `TransactionEntry`: amount, currency, payment_method, installment count from AID selection, linked original transaction ID, bank_id, confirmation_code/receipt/timestamp ([protocol/termwire.proto#L171-L183](protocol/termwire.proto#L171-L183)).
- Response: transactions list, next_cursor, code/message ([protocol/termwire.proto#L185-L189](protocol/termwire.proto#L185-L189)).

## Gift Card / Loyalty
- Inquiry and charge flows support currency ([protocol/termwire.proto#L201-L213](protocol/termwire.proto#L201-L213)).

## Code and Compatibility Notes
- Field numbers must be preserved; new messages should use available number ranges (e.g., 80–89).
- All monetary and points fields are integers in cents; if installments exist, `installment_count` > 1 is sent.
- RRN/Auth matching uses `confirmation_code` and `original_confirmation_code` together.
